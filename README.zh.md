# dsh-compact-left

[English](README.md) | 中文

一个 DSH 客户端插件，为折叠状态的左侧边栏增加「悬停临时展开」能力。

官方外壳把侧边栏当作二元的 `收起 ⟷ 展开` 开关，没有中间预览态。本插件从指针焦点驱动同一个
`ctx.layout.toggleSidebar()` 动作，补上一个临时的中间状态。

## 行为

```
COLLAPSED ──鼠标悬停左边缘 150ms──▶ PEEK
PEEK      ──指针离开 200ms───────▶ COLLAPSED
PEEK      ──点击折叠按钮─────────▶ PINNED
PINNED    ──点击折叠按钮─────────▶ COLLAPSED   （官方原有行为）
```

- **PEEK** 是临时展开，表现为**浮动抽屉**：侧边栏被移出网格流（`position: fixed`）并覆盖在
  主区域之上，主区域保持原本的满宽、不被挤压。指针停留在内部可以正常点选项目，移开后自动收起。
  展开与收起都有动画（滑入 + 淡入，180ms），且**只动画抽屉本身**——主区域全程不动。
- **PINNED** 就是外壳自身的展开状态。插件不额外保存它的标志位，因此鼠标离开已固定的侧边栏
  **永远不会**把它收起。插件只会撤销由它自己发起的展开。固定的侧边栏会取消浮动，变回普通的
  展开网格轨道，因此会像外壳原生行为那样挤压主区域。
- 触发悬停的是窗口左边缘的一条热区加上折叠按钮本身，指针不必精准落在那个小按钮上。热区宽度
  **与折叠态列宽一致**：Web 上就是可见的图标栏（约 56px），悬停任意图标即可展开；desktop 上
  折叠态列没有宽度，因此回退为一个固定的、更宽的 28px 热区。
- 插件不自己绘制任何 tooltip。悬停展开期间它会收起外壳自己的气泡，否则该气泡会浮现在刚被
  展开的侧边栏上方。

## 折叠态显示品牌标识

官方折叠按钮渲染的是一个通用的「左侧面板」图标。非 Windows 轨道上外壳会自己换成品牌标识，
但 Windows 标题栏下它保留原图标——于是折叠在那里读起来像「某个面板」而不像这个产品本身。
本插件补上这一处。

图标是**从外壳自己的品牌行克隆而来**（`[data-slot="sidebar.brand.mark"]`），而不是复制：
不存在第二份会漂移的副本。外壳只在侧边栏展开时才挂载那一行，因此在悬停期间把 SVG 缓存下来，
折叠时复用；首次折叠（尚未 peek 过）时无图可显示，此时**保持原图标不动**，而不是换成一个
相似的样子。

三重守卫确保不会出现两个标识：

1. 侧边栏一展开就移除标记；
2. 外壳若已在按钮上渲染自己的品牌标记，则不再添加；
3. 没有可克隆的 SVG 时，图标原样不动。

React 拥有按钮的子节点，所以标记是作为外壳从不触碰的兄弟节点插入的，原图标则用 CSS 隐藏
而非删除。外壳自身的悬停规则仍会把图标翻回面板图形，因此这个手势依旧读作「展开侧边栏」。

## 为什么指针几何要实时测量

外壳没有「侧边栏是否展开」的稳定 API，插件只能从侧边栏自身的 DOM 读取：

- 类名是 CSS Module 哈希，因此按后缀匹配（`_root`、`_collapsed`、`_toggle`、`_frame`），
  而不是绑定某一次构建的哈希。
- Windows 上折叠态的按钮是 `position: fixed` 悬浮在标题栏里，而展开态是网格轨道（grid track），
  所以「是否在内」是两者的并集，且在每次事件与定时器触发时实时测量，不用缓存矩形。
- 窗口离开（`pointerleave`）时**不能**重新测量最后位置：最后一次 `pointermove` 仍停在侧边栏上，
  重测会得出「指针从未离开」的结论，导致永远不收起。这条路径改用自身的证据判定。

## 浮动抽屉如何避免挤压主区域

悬停展开依旧驱动外壳自己的 `toggleSidebar()`，因此侧边栏会展开、React 也会挂载外壳仅在「宽」态
才渲染的完整导航——但插件不会让它以变宽的网格轨道留在布局里。frame 的**直接**网格项是：侧边栏
列、主区域列、右侧列、底栏，彼此是**独立**的条目，所以正确做法是：让侧边栏列**留在**网格流里
（其轨道被钉回折叠模板），只把它的**内层** `*_root` 内容以覆盖层方式抬起来。展开期间：

- 容器的网格轨道被保持在**捕获到的折叠模板**上——首条轨道沿用折叠时的轨道宽度（Windows/macOS 为
  `0`，Web 的图标栏为 `56`），主区域的 `minmax(400px, 1fr)` 与右侧轨道原样保留。React 每次提交都会
  重算并用加宽的侧边栏轨道覆盖内联的 `gridTemplateColumns`，所以内联覆盖会输掉这场竞争；轨道列表
  改为经由一个自定义属性、由样式表里的 `!important` 规则消费——`!important` 优先于普通内联样式，
  因此在 React 反复提交之间依然稳定生效；
- 内层的 `*_root` 列被浮动为 `position: fixed`（left 为 `0`，top 取 frame 的 `padding-top` 以让开
  标题栏，宽度为刚展开时量得的列宽，以及 `transition: none` 以抑制外壳的展开宽度补间动画）。高度显式
  设为 `calc(100vh - <标题栏高度>)`，而**不是**用 `top`+`bottom` 拉伸：外壳的 `*_root` 自带
  `height: 100%`，显式高度优先于拉伸，否则在 desktop 上会把页脚（连同左下角的用户名和头像）挤出视口。
  外层 `sidebarCol` 留在流里、被收窄到折叠轨道并视觉上空白，垫在抽屉背后。

抽屉**不添加任何自身样式**——没有阴影、没有边框、没有背景。它就是外壳自己的侧边栏列，展开后的外观
必须与侧边栏本身完全一致；任何额外装饰都会让它看起来像另一层。​（早期版本给 `div[class*="_root"]`
加了阴影，这个选择器范围过宽，会命中 frame 内所有 `*_root` 面板，这正是无关面板看起来被分层的
原因。）

于是主区域**完全保持折叠时的位置与宽度**，而抽屉（比图标栏更宽）只是覆盖它的左边缘。两种错误都被
避开：把**外层** `sidebarCol` 移出流，会让主区域自动填进首条轨道并塌缩为 0（闪烁后消失）；放任
加宽的侧边栏轨道，则会把主区域推开（挤压）。

`resize` 会重新钉住容器并重测量列宽，使抽屉跟随窗口。点击把悬停固定下来时，浮动会被取消
（`peeking` 变为 false），列恢复外壳正常的展开轨道——这就是为什么固定的侧边栏会挤压主区域，与外壳
原生行为一致。

## 动画为什么不会带动主区域

抽屉用 180ms 的滑入（`left: -12px → 0`）加淡入（`opacity 0 → 1`）来做开合。只有抽屉本身在
动：frame 的网格轨道被 `transition: none` 钉死，因此整个动画过程中主区域保持折叠时的几何位置，工作区
不会有任何位移。收起时反向播放同一段动画，动画结束后才真正折叠列，所以看起来是滑出而不是瞬间消失。
入场动画每次 peek 只播放一次——指针移动时的状态同步只刷新几何，不会重播动画，否则鼠标移动会让抽屉
闪烁。

**滑动不能用 `transform`。** desktop 上 shell 用 `position: fixed; left: 12px` 把折叠按钮钉在
**视口**上。按 CSS 规范，祖先元素上的 `transform` 会让该祖先成为 `position: fixed` 后代的包含块——
于是用 transform 做抽屉动画会把折叠按钮重新锚定到抽屉上，peek 期间按钮就跟着移动了。因此滑动改为
动画 `left`：它只是普通布局偏移，不创建包含块。（fixed 元素的负 `left` 不会扩展文档可滚动区域，
所以这 12px 的超出不会引入横向滚动条。）

**钉住的轨道必须撑过整个收起动画。** 如果在收起开始时（也就是最顺手的位置、紧挨着淡出）就释放钉住，
React 的加宽侧边栏轨道会立刻恢复，主区域在抽屉还在淡出时就跳宽，等列真正折叠时又缩回——Web 和
desktop 上都能看到这次闪烁。因此整段动画期间由 `closingFloat` 标志保持钉住，并在列折叠之后、与抽屉
的内联几何一起清除。另外，浮动抽屉对 shell 的 `_collapsed` 类具有更高优先级：shell 会晚一帧才让该
类稳定，若把残留的 `_collapsed` 当成「已折叠」，就会在滑出途中释放浮动。

## peek 期间为什么不替换品牌图标

品牌图标的替换只属于**折叠轨道**。peek 浮动的是展开态列，而 desktop 上列变宽时 shell 仍会在标题栏
里渲染自己的折叠图标。若不加判断地替换，插件克隆的品牌图标就会和 shell 的图标并排显示，二者重叠。
`syncBrandMark` 把「浮动中」视同展开态，在整个 peek 期间移除该图标，待列重新折叠后再恢复替换。

## 抽屉为什么不会遮住外壳的菜单

抽屉的 `z-index` 刻意取**低值**（25）：高于 frame 自身的覆盖层（20）以便盖住主区域列，但低于所有
外壳菜单层——图标菜单 `70`、下拉/悬浮卡列表 `100`/`101`、以及挂到 body 的菜单/提示/Toast 层
`1100`。这些菜单是 `body` 下的 portal，只有抽屉的 `z-index` 更低，它们才能画在上面。早期版本用了
接近最大值的 `z-index`，这正是工作区的视图菜单与会话菜单被抽屉挡住的原因。

## 设置

插件在「设置 → 左侧折叠栏」下注册一个开关，值保存在 `localStorage` 的
`dsh-compact-left:hoverPeek`。该值在使用时即时读取，因此切换后**无需刷新**，下一次悬停即生效。

## 开发

插件通过链接进入 DSH profile，而不是发布到 npm。在该 profile 的 `package.json` 里加一条
`link:` 依赖并重新安装即可：

```json
"dependencies": {
  "@local/dsh-compact-left": "link:<本仓库的路径>"
}
```

安装后，profile 会把它解析为指向本仓库的链接：

```
$HOME/.dsh/profiles/<profile>/node_modules/@local/dsh-compact-left
  -> <本仓库的路径>
```

Windows 上 `$HOME` 即 `%USERPROFILE%`。

`client.js` 通过 `window.__ModuleLoader__` 作为单个 bundle 加载，在运行中的 DSH 里从 graph
快照解析：**修改后需要重新加载窗口**才能看到变化。
